# 微信与手机号登录：代码完成及开通配置

> 2026-11-13 更新：当前版本隐藏全部微信登录、绑定入口及相关界面提示，只展示手机号入口并保留原账号密码登录。微信底层接口和 SDK 暂留，后端开关保持 false。本次应使用新版 `sms-login-20261113-handoff.zip`，部署以 `docs/2026-11-13-短信登录部署交接.md` 为准，旧交接包不再作为本次交付依据。

日期：2026-11-12。基于本机 App `e032966`、Web `20761b9` 实现。本次只修改代码和文档，没有构建 APK、推送 GitHub或部署生产服务。现有安装包尚不包含本轮功能。

## 已实现

- 当前登录页仅展示手机号快捷登录入口，保留账号密码登录。手机号使用中国大陆手机号＋6 位短信验证码，不是运营商本机号码一键登录。
- “我的账号”仅展示绑定手机号和脱敏手机号状态。绑定后登录使用原用户 UUID、患者 UUID、本机账号目录和自动同步流程；微信绑定及状态隐藏。
- 首次第三方登录自动创建 PATIENT 账号及 Web 患者档案，显示一次性恢复码；确认保存后进入训练。不会给普通账号工作人员权限。
- 已有账号应先用原方式登录，再绑定微信/手机号。直接用尚未绑定的第三方身份登录会创建新账号；不通过昵称、手机号或患者姓名猜测并合并患者档案。
- 验证码有效期 5 分钟，最多尝试 5 次，每个挑战只允许成功使用一次；手机号编辑后 App 会作废旧挑战。发送期间禁用重复操作，重发倒计时遵守服务端 Retry-After。
- 微信使用原生 SDK `6.8.40`，校验临时 code 和 state；支持取消、拒绝、未安装微信、超时与页面关闭处理。服务端才持有 AppSecret，不在客户端交换微信凭证。
- 两项服务默认关闭。旧后端或服务未开通时，提示暂不可用，保留原账号密码登录。进入登录页不会主动向第三方初始化 SDK 或尝试登录。

## 你现在先准备什么

1. 在微信开放平台创建琴伴的**移动应用**，按控制台要求完成应用资料、主体与微信登录权限审核。获得移动应用 AppID/AppSecret；小程序或公众号的 AppID 不能代替此配置。
2. 登记 Android 包名和实际待安装 APK 的签名。当前正式包名为 `com.pianoforparkinson.piano_practice`，APK 仍沿用既有开发签名；正式发布前需要确定长期签名。按微信平台指定格式提取签名，不把不同算法的指纹混填。
3. 阿里云开通“号码认证服务 → 短信认证”，选择适用的系统赠送签名和模板。此功能调用 `dypnsapi.aliyuncs.com` 的 SendSmsVerifyCode/CheckSmsVerifyCode，不使用单独的短信服务 dysmsapi 套餐。
4. 为后端准备专用 RAM 凭证，授予 `dypns:SendSmsVerifyCode`、`dypns:CheckSmsVerifyCode` 所需权限。密钥在服务器环境变量设置，不发送到聊天、不放入 APK 或 GitHub。
5. 准备对外可访问的用户协议和隐私说明，按第三方平台要求完成审核配置。

截至 2026-11-13，用户已完成阿里云控制台向已绑定测试手机号发送验证码，创建专用 RAM 用户并授权；还没有通过本轮 Web 后端验证专用 RAM 凭证、短信核验和 App 登录。微信当前个人主体未具备所需认证资格，暂不部署启用。

2026-11-12 验证见 `validation/wechat-phone-login-20261112.md`；2026-11-13 最终界面验证见 `validation/sms-login-20261113.md`：App 全量 829 通过、2 跳过，账号界面相关 26 通过，静态分析无问题。后端代码未再修改，沿用之前账号相关 44 项通过的证据；另有 5 项环境/依赖失败已在原始基线复现。

## 后端怎么接入

交给维护 Web 服务器的队友合并本轮 Web 代码，并参考 `web/docs/mobile-external-login-20261112.md`。本轮新增迁移 `n0c2d4e6f8a0 → o1d3e5f7a9b1`，只新增身份映射、一次性挑战、限流计数三张表，不改旧账号、患者和训练记录。

把 `web/deploy/mobile-login.env.example` 中的新增变量合入现有后端配置，保留既有数据库地址和 JWT_SECRET。每项服务在实际配置完成后单独开启：

```dotenv
MOBILE_WECHAT_ENABLED=false
MOBILE_WECHAT_APP_ID=
MOBILE_WECHAT_APP_SECRET=
MOBILE_SMS_ENABLED=false
MOBILE_SMS_ACCESS_KEY_ID=
MOBILE_SMS_ACCESS_KEY_SECRET=
MOBILE_SMS_SIGN_NAME=
MOBILE_SMS_TEMPLATE_CODE=
MOBILE_SMS_SCHEME_NAME=
MOBILE_SMS_DAILY_BUDGET=100
```

`MOBILE_SMS_SCHEME_NAME` 可留空使用默认方案；使用自定义方案时，发送与核验保持同名。本实现模板变量为 `code` 和 `min`，动态验证码由阿里云生成；必须选择匹配这两个变量的模板。

后端对短信接口增加数据库持久化限制：每手机号 60 秒 1 次、24 小时 10 次，每 IP 1 小时 20 次，全服务 24 小时默认 100 次发送预留。这些计数使用从该窗口首次请求起算的固定窗口，不按自然日零点重置；它不是严格的滑动窗口。失败的发送也占预留次数，避免失败重试扩大开销。额度可以通过配置调整。绑定验证码和登录验证码用途分开，绑定挑战同时绑定当前用户及移动会话；要求最近 15 分钟内完成登录。

服务商未配置时，`GET /api/mobile/auth/providers` 返回对应 `false`，敏感值不返回。App 不需要额外配置 AppSecret 或 AccessKey；微信 AppID 由后端挑战接口下发。

## Android 接入说明

- Gradle 已加入微信官方 SDK Maven 依赖，无需另加 Flutter 微信插件。
- `WechatLoginBridge` 提供 `piano_companion/wechat_login/v1` 通道；只有用户点击微信授权时才创建 SDK 实例。
- Manifest 注册 `${applicationId}.wxapi.WXEntryActivity` 别名，指向 `accounts.WechatCallbackActivity`。别名支持不同构建包名，但微信平台登记的包名/签名仍必须与安装包对应；`.validation` QA 包不能自动冒用正式包的登记资料。
- 手机号支持手工输入验证码和系统自动填充提示，不申请读取短信、接收短信或读取电话状态权限。
- 本轮尚未构建或安装 APK。平台配置和后端准备好后，再构建包含上述 SDK 与界面的新版 App 做真机联调。

## 账号与恢复规则

新第三方账号使用系统生成的唯一用户名，显示在“我的账号”中；首次登录会给出恢复码。需要设置账号密码时，可通过“忘记密码”使用该用户名及恢复码重置密码，并保存新的恢复码。不要共享恢复码。

本版本每个账号可绑定一个手机号和一个微信身份；已绑定时显示状态。发生已有绑定冲突时返回 409，不覆盖、不自动合并档案。解绑、换绑及账号合并不在本轮范围内。

微信客户端进程或本 App 在授权中被系统终止时，不从不受信任的回调恢复登录；重新打开后再次发起授权。验证码、微信 code 和 state 不持久化到 App 普通配置中。

## 上线后真机验收

1. 先确认旧账号仍可正常登录并查看原训练记录。
2. 原账号登录 15 分钟内绑定手机号/微信，核对 Web 患者编号不变；退出后用新绑定方式登录，原记录和计划仍在。
3. 用新的第三方身份首次登录，保存恢复码，核对只创建一个患者，重复登录仍是同一编号。
4. 完成计划并核对 App/Web 进度、断网练习联网补传、退出重开和两账号隔离。
5. 检查错误验证码、过期、重发、频率限制；微信取消/拒绝/未安装/授权超时，以及换账号操作。
6. 使用实际登记签名测试微信回调；服务配置关闭或网络不可达时，App 不应显示登录成功或绕过训练入口。
