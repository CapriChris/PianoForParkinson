# 未来开发计划

更新日期：2026-11-03。

## 视频按需下载与国内托管（已延期）

当前决策：继续把四个舞蹈视频打包在APK内，安装后直接离线播放，不启用视频下载管理或联网请求。0.1.57曾完成本地客户端原型验证，但没有配置国内托管、没有发布Release；根据用户决定，0.1.58已恢复随包视频方案。

延期原因：对象存储有持续的存储、外网下载流量和请求费用。现阶段优先保证安装后即可使用，暂不引入这项运营成本。未来用户数量、视频体积或发布频率增长，并明确托管预算与资源归属后，再评估启用。当前无需购买云服务或配置域名。

### 目标与用户流程

- 视频从APK移出，安装包保留课程插画与资源清单；中文三部分与英文课程分开，用户只下载需要的部分。
- 首次观看前显示文件大小并确认，计费网络提示流量消耗；启动App不自动下载全部课程。
- 下载显示进度，支持暂停、断点续传和失败重试。第一阶段离开页面/切后台时暂停，下次手动继续；后台持续下载另作为后续能力评估。
- 长度和SHA-256校验成功后持久保存，随后直接离线播放。下载、等待、缓冲与校验不计入训练时长。
- 设置提供视频占用、单个删除和全部清理；清理视频不删除记录或计划，播放中的文件不能删除。

### 实施顺序

1. 确认国内对象存储及可用的HTTPS下载地址，核实默认域名、读取权限、长期可用性和按实际下载量计算的费用；需要时再接CDN。
2. 上传现有四个ASCII文件，保持文件字节不变。服务端支持Range/206、正确大小和稳定ETag；App不包含云服务密钥。
3. 恢复资源清单和下载模块，以独立资源版本、字节数和SHA-256管理文件；采用临时文件、区间校验与校验后原子重命名，拒绝错误或不完整的视频。
4. 将播放器资源来源改为已下载的本地文件，保留现有课程ID、分段ID、训练计时、控制组件及历史详情行为。
5. 增加下载管理与必要的普通联网权限，完善网络、空间、文件损坏与生命周期中断处理。
6. 配好真实源后重新构建并在目标Android真机上验证，再考虑公开分发。普通App升级不重复下载未变化的视频；源地址和视频版本更新策略需一并确定。

### 验收要求

- 相同架构构建下，APK不再包含MP4/WebM，并显著减小。0.1.57原型约91.56MiB可作参考，最终以实际构建为准。
- 验证首次下载、暂停续传、断网恢复、服务端忽略Range、校验不符、空间不足与覆盖升级。
- 已下载课程在无网络时可播放，删除视频不影响记录与计划，历史记录不重复保存，下载等待不增加训练时长。
- 核对真实国内端点、不同网络及目标手机上的表现，不把本地HTTP或播放器替身测试当作真实云端验收。
- 记录托管费用和运维方式；所有视频下载完成后仍占用本机空间，收益主要是安装包和后续更新体积减少。
