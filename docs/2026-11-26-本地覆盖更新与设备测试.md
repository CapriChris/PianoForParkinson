# 本地覆盖更新与设备测试

日常包名为 `com.pianoforparkinson.piano_practice`。正常覆盖更新必须保持包名、签名和应用数据目录一致，使用 `adb install -r`，安装失败时停止，不自动卸载或清除数据。登录凭据及初始化设置原本分别保存在应用安全存储与账号数据库中，不应在普通更新时重置。

## 本地更新

在已配置 Flutter 和 Android SDK 的 PowerShell 环境中执行：

```powershell
flutter build apk --debug --no-pub --target-platform android-x64
.\scripts\update_local_android.ps1
```

更新脚本检查 APK 的真实包名，拒绝将隔离测试 APK 当作日常包发布。覆盖安装后比较首次安装时间，确认原安装身份仍保留。签名、版本或安装错误不会触发卸载重装。`-NoLaunch` 可用于安装后先验证持久化数据。

## 设备测试

不要直接在日常安装包刚生成后运行原始的 `flutter test integration_test/...` 命令。当前 Flutter 工具会在重新构建前读取已有 APK 的包名，并把该身份保留到测试结束时的清理阶段。这可能使清理指向日常包，即使后续构建用了隔离包名。

统一使用：

```powershell
.\scripts\test_isolated_android.ps1
# 其他设备测试可指定 TestPath 和所需开关
.\scripts\test_isolated_android.ps1 -TestPath integration_test/waterfall_mp3_flow_test.dart -Defines MP3_IMPORT_TEST=true
```

脚本先预构建 `.validation` 隔离 APK，再核对 APK 实际包名，然后使用 `--no-uninstall` 执行测试，并验证日常包的首次安装时间没有变化。测试产物仍在默认构建路径中，完成测试后应重新构建普通 APK，再运行覆盖更新脚本。

已经被卸载或清除的数据不能通过覆盖更新自动恢复。本次修复保证后续测试与覆盖更新保留现有账号、初始化配置和本地记录。凭据自然到期或服务端撤销时仍应按原有规则重新认证。
