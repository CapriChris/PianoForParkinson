# 琴伴注册登录与自动同步交接（截至 0.1.63+64）

2026-11-06 · 发布前实现与验证记录；公网部署和真机联调待完成。App 交付版本为 `v0.1.63`，Web 配套变更见 [草稿合并请求 #1](https://github.com/WuChangqing1/PD-Rehab-Web/pull/1)。

## 用户流程

首次打开进入登录页，提供注册和找回密码。训练、计划、记录和 AI 助手仅在账号登录后开放；不提供游客训练入口。0.1.62 起按产品要求移除额外同步勾选，注册/登录即开启训练记录和计划自动同步，AI 读取记录和视频采集仍沿用独立授权。

注册成功后，后端在同一事务中创建账号和患者档案，自动分配 `Pxxxxxx` 编号，并返回登录凭证。已有示例患者保留，不做匹配、迁移或删除。App 自动使用返回的患者编号建立设备档案关联，工作人员在 Web 的患者列表中查看新患者；医生仍按原有患者访问授权规则查看，管理员可查看全部。

用户只需登录一次；后续启动可从安全存储恢复登录。有效登录可离线练习。保存的训练记录和计划进入原同步队列，恢复网络、保存训练、修改计划、重新进入前台时自动触发同步。

退出登录立即销毁受保护页面栈，返回登录页。返回键或通知不能打开上一账号的训练页面。新账号独立存储训练、计划、会话、同步缓存与队列。旧版根目录中的游客/联调数据库不导入、不修改，也不上传。

## App 实现

- `lib/main.dart`：正式主入口改为账号入口；保留独立测试程序的控制器注入方式。
- `lib/accounts/`：注册、登录、一次性恢复码找回密码、修改密码、自动恢复、账号状态和同步页面。
- 登录凭证：短期 Access Token 只在内存中；Refresh Token 与最小账号档案信息经 Android Keystore AES-GCM 加密，原子写入 `noBackupFilesDir`，不写明文 SQLite，不保存登录密码。
- 访问凭证到期时自动刷新，多请求共用一次续期；凭证轮换先安全落盘后使用新凭证。退出与异步写入串行处理，迟到的请求不能恢复已退出会话。
- 数据目录为 `account-SHA256(服务地址 + 用户 UUID)`，每个账号拥有独立 `practice.db`、会话库和同步库。设备 ID 来自该账号数据库，重新登录不更换上传设备 ID，避免重复上传。
- 主应用注册 WorkManager 有网任务及 15 分钟周期兜底。存在交互引擎时调用同一个同步协调器；进程不存在时启动受限后台引擎，仅同步结构化记录和计划。
- 前台与独立后台引擎共用原生文件锁。后台打开数据库时禁止恢复/终结仍在进行的训练。视频采集、上传和分析沿用已有授权流程，未新增后台视频上传服务。
- 系统省电、后台限制或强制停止会影响执行时机；重新打开后继续补传，不承诺后台实时上传。
- 「设置 → 我的账号与同步」显示用户名、档案编号、同步状态，提供立即同步、修改密码和退出登录。首次引导与初始化出错页也能退出账号。

## 后端实现与兼容方式

本机 Web 基线为 `7e1c731`。为兼容训练记录、设备绑定和视频表已有的用户外键，复用原 `staff_users` 物理账号表，新增严格隔离的 `PATIENT` 角色，不赋予医生或管理员权限。新增 `mobile_accounts` 保存账号与患者的一对一关联、恢复码哈希与同步授权版本；新增 `mobile_sessions` 保存刷新凭证哈希、有效期及撤销状态。

普通用户无法通过原工作人员登录接口登录。服务端在执行处理函数前拒绝其访问工作人员 API，只允许明确列出的移动账号和自身同步接口；后续对象校验仍检查患者归属、设备档案绑定和原有记录权限。工作人员列表过滤 `PATIENT`，既有 Web 登录及医生/管理员权限保持。

## 接口契约

以 `https://ccqspace.site/pd-rehab/api` 为基地址。

| 方法和路径 | 用途与主要字段 |
| --- | --- |
| `POST /mobile/auth/register` | `username`、`password`、`display_name`、`sync_consent_version=account-sync-v1`；事务创建账号和档案 |
| `POST /mobile/auth/login` | 用户名和密码；只接受普通用户账号 |
| `POST /mobile/auth/refresh` | `refresh_token`；轮换刷新凭证并签发新访问凭证 |
| `GET /mobile/auth/me` | 当前账号及唯一患者档案 |
| `POST /mobile/auth/logout` | `refresh_token`；撤销此设备会话，重复退出可安全重试 |
| `POST /mobile/auth/reset-password` | `username`、新 `password`、`recovery_code`；单次恢复码消费后轮换，撤销全部会话 |
| `POST /mobile/auth/change-password` | `current_password`、`new_password`；修改后撤销全部会话并重新登录 |

注册/登录/续期的响应包含 `user`、`patient`、`access_token`、`refresh_token`、`expires_in`、`refresh_expires_at`。`user.role` 必须为 `PATIENT`。Access Token 有效期 15 分钟，刷新会话 30 天；刷新成功延长会话。注册额外返回一次性 `recovery_code`，由用户自行保存，不存入手机会话。

用户名为 3–32 位 ASCII 字母、数字或下划线，统一小写。0.1.63 起，新注册、重置和修改密码统一为 8–16 个 Unicode 码点；旧账号登录仍兼容原先至多 64 字符、72 UTF-8 字节的密码。App 按相同口径计数，未输入和长度不符分别提示。不接受客户端指定角色或患者 ID。登录、注册、恢复和改密接口有限流；生产代理需另外设置多进程共享的限流策略并正确传递真实客户端 IP。

本版使用恢复码找回密码，未接入短信、邮箱或手机验证码。遗失密码与恢复码时需联系维护人员核验处理。恢复码不能写入报告、截图、日志或聊天。

结构化数据继续使用 `/integration/v1/bindings`、`/records`、`/changes` 等接口，保留来源 ID、内容哈希、重试和计划版本规则。

## 给 Web 队友的部署步骤

1. 检查本机配套 Web 变更或交接 ZIP。ZIP 中保存原项目相对路径；若仓库已超过基线版本，应合并变更，避免直接覆盖队友的新代码。
2. 保留现有生产配置和数据库。备份数据库后，在后端目录、对应虚拟环境中执行 `python -m alembic upgrade head`。新增迁移为 `n0c2d4e6f8a0_mobile_accounts.py`；不删除示例数据。
3. 按原部署方式重启后端；本轮无需重新构建 Web 前端。原工作人员账号可继续登录。
4. 未登录请求 `GET /api/mobile/auth/me` 应返回 401。若返回 404，说明新路由尚未部署。反向代理需要保留 `/pd-rehab/api/mobile/...` 到后端 `/api/mobile/...` 的转发。
5. 安装本轮 APK 注册测试账号，保存恢复码；用工作人员账号在 Web 患者列表中核对新编号与姓名，再开始双端验收。

App 未提供管理员账号回退或本地伪注册。后端未部署时，注册/登录会明确提示服务尚未启用。

回滚到不认识 `PATIENT` 角色的旧后端前，必须先停用普通用户登录。新增迁移的 `downgrade()` 会停用这些账号并保留患者及训练数据，再移除会话与关联表；不要只替换旧代码而保留普通用户的活动登录。回滚后账号重新启用需要维护人员核验并重建正确关联。

## 验收步骤

| 场景 | 预期 |
| --- | --- |
| 首次启动/退出后/系统返回/通知打开 | 均不能绕过登录进入训练 |
| 注册并登录 | Web 创建且只创建一个新患者；客户端不能指定其他患者 |
| 重复用户名/注册字段错误 | 注册失败，不遗留额外患者 |
| 重启、有网络或断网 | 有效会话可恢复；断网可练习，联网后补传 |
| 训练保存、计划 `1/2 → 2/2` | 同步到本人档案，重复同步不增加相同记录 |
| 切换账号 | 训练、计划、会话和待上传记录隔离；回到原账号可见原数据 |
| 使用恢复码/修改密码/停用账号 | 旧会话不能继续访问接口；恢复码只能使用一次 |
| 用户修改患者 UUID 或访问医生页面 | 服务端拒绝，不泄露其他患者数据 |
| 前后台/进程终止后补传 | 使用同一队列，不误终结活动训练，不重复数据 |

本机验证结果与安装包信息见 [0.1.63 验证报告](../validation/release-0.1.63.md)。真实阿里云部署、设备 Keystore 与 WorkManager 系统调度仍需要真机联调验收。0.1.63 后端包更新密码规则，不新增数据库迁移；已部署账号功能的服务器合并代码并重启即可。
