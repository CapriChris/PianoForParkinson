# 视频按需下载与国内托管（已延期的0.1.57原型方案）

2026-11-03决策更新：用户决定暂缓国内托管及下载方案，当前0.1.58已恢复四个视频随APK打包、直接离线播放。下载界面、联网权限、运行时下载清单及下载模块已从当前App撤下。后续评估见[未来开发计划](未来开发计划.md)。

以下保留0.1.57原型的设计资料，不表示当前功能，也不要求现在购买云服务。原型代码及配置工具已归档到本机app/build/video-on-demand-prototype-0.1.57.zip，未随APK分发；后续重新启用前先恢复和适配原型，再使用下文命令。0.1.57没有发布Release，国内托管也未实际配置。

## 用户流程

- 首次安装和启动不下载视频。进入舞蹈跟练时，只检查本地文件。
- 每一部分独立下载。点击下载后显示剩余大小并确认；计费或未知网络提示建议Wi-Fi；无网络不启动下载。
- 下载有进度、暂停、继续和失败重试。离开页面、切换部分或切到后台时暂停，保留部分文件。下次打开App或返回课程可继续；本版没有后台持续下载服务。
- 全部字节下载并通过SHA-256校验后才可播放；以后优先读取本地文件，离线也可使用。
- 设置增加“视频下载管理”：显示占用，删除单个或全部视频和未完成下载。全部清理还包括旧资源版本的受管理视频；不删除数据库、练习记录或计划。播放中的文件禁止删除。
- 下载、等待、校验不计入实际播放时长。未打开过视频不能“结束并保存”空下载会话；原有部分切换、倍率、拖动暂停和历史记录ID保留。

## 配置国内托管

无需先部署业务服务器。使用团队自有云账号，在中国大陆区域创建对象存储，按实际用户网络决定是否接国内CDN。存储与下载流量可能收费，云账号与密钥只由团队管理，不进入App。

1. 四个视频原文件仍在本机assets/video中，没有被删除。先执行 `python tools/prepare_dance_asset.py --check` 核对原文件。
2. 上传以下四个ASCII文件，保持原始字节不变，存放于同一个固定目录。仅需要提供这些视频的HTTPS读取入口，不开放写权限或目录列举权限。

| 文件 | 字节数 | 大小 |
| --- | ---: | ---: |
| balance-six-part-1.mp4 | 34614645 | 33.0 MiB |
| balance-six-part-2.mp4 | 173248152 | 165.2 MiB |
| balance-six-part-3.mp4 | 12174975 | 11.6 MiB |
| fandango-lesson-4.webm | 344420928 | 328.5 MiB |

3. 配置有效HTTPS证书和读取权限，确认支持 `Range` / `206 Partial Content`、正确的Content-Range和Content-Length。建议返回稳定ETag，MP4类型video/mp4、WebM类型video/webm，不对响应做压缩或转码。地址及重定向链均应部署在预期区域，不能仅凭HTTPS认定节点在国内。
4. 获得统一地址前缀后，在仓库根执行下列命令。`https://<国内视频域名>/dance/v1/` 是占位说明，须替换为真实地址。不要将密钥交给此工具。

```powershell
python tools/configure_video_host.py --base-url "https://<国内视频域名>/dance/v1/" --probe
python tools/configure_video_host.py --base-url "https://<国内视频域名>/dance/v1/" --probe --write
flutter build apk --release
```

第一条仅检查，不更改配置。第二条在检查四个端点后写入assets/config/dance_videos.json，随后构建才生效。探测仅验证HTTPS、总大小和单字节范围响应；完整远程文件的SHA-256由App下载后校验。

也可手动填写清单中每项url（适合不同目录），或构建时传入 `--dart-define=DANCE_VIDEO_BASE_URL=https://<国内视频域名>/dance/v1/`。单项url优先于统一前缀；没有配置时没有GitHub或其他境外回退源。固定在APK中的可信清单只包含公开下载地址和文件元数据，不含云凭证。短期签名链接会过期，不宜直接固化到APK；若需私有鉴权，需另行实现服务端签发。

## 存储与可靠性

资源信息位于assets/config/dance_videos.json，课程ID不变。下载存入Android应用专属noBackupFilesDir/dance-videos，文件名由ID、资源版本及哈希前缀组成。它是持久存储，非临时cache；覆盖升级保留，卸载或清除数据会删除。

未完成文件以.part保存，强ETag另存。恢复时发送Range与If-Range；服务器返回200则重新写入而非追加，206必须匹配起点和总大小。下载不把整个视频读入内存；长度、SHA-256全部正确后原子重命名，才提供给VideoPlayerController.file。下载前检查剩余空间，断网、超时、403/404、校验失败与空间不足分别可恢复。HTTPS重定向有次数上限，不允许降级到HTTP；测试允许回环HTTP，正式构建不允许明文视频地址。

INTERNET与ACCESS_NETWORK_STATE是普通权限；无需申请相册或外部存储权限。练习数据仍保存在本机，不上传；视频请求会向视频托管方暴露常规连接信息，例如IP。训练上传和账号开关保持关闭。

## 版本与维护

App版本与视频资源版本独立；不更改资源版本和哈希时，升级App无需重新下载。替换视频时更新资源version、文件大小和sha256，并使用新的远程路径，避免CDN缓存串版本。历史记录的课程与部分ID保持稳定。

从源码构建不再要求恢复视频。只有准备上传原片、运行素材校验或完整视频设备测试时才需要本机视频文件。旧版0.1.56仍是完整离线大包；升级后原APK中的视频不能直接当成新包的下载文件沿用，首次使用新版课程仍需下载。

## 验证范围

下载层以本地HTTP服务器验证传输、暂停、206续传、服务端忽略Range、错误区间、哈希失败、断点跨实例恢复、空间检查、持久离线读取、版本隔离和删除互斥。界面验证下载确认、计费网络、离线、未配置来源、切换部分和320dp/200%中英文布局。旧播放流程继续以本地文件源验证。

国内托管尚未配置，尚未完成真实公网视频源、跨品牌真机下载和后台中断实测。旧版本全套测试未通过的情况仍保留在0.1.56验证文档中，本轮不把专项通过等同于全套通过。
