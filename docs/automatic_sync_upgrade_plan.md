# 自动双向同步实施计划

- Flutter GitHub main `c5607f8` 是录像基线；Web GitHub main `cb75a00` 是线上代码基线，Web 本地录像候选保留。两个源码克隆均在 Web 工作区的 `_deploy` 中。
- 现有手动 API 支持患者/工作人员档案、只读云端历史、训练记录及计划上报；录像独立按授权、网络类型、加密分块和人工复核推进。App 没有可编辑 Web 患者资料的页面，患者及工作人员仍由 Web 管理。
- 普通同步复用 `CrossClientSync`、既有前台协调器和 SQLite 侧库；主训练数据库 v4 不变。侧库 v2 有录像与自动同步两个历史分支，统一升级必须同时保留两边表。旧的未核实历史留在本机；新写入按已验证绑定的时间和本地档案分区。保留重试原来源 ID、内容指纹和计划版本。
- 已知入口 `https://ccqspace.site/pd-rehab/api`；普通同步继续使用 `/integration/v1`，录像仍使用 v1.2 能力。当前 Web 的 offset 历史不具备修改和删除增量；新增受权限控制的持久序列 feed，在 Flutter 与旧服务器交互时明确显示未启用增量能力。
- 分阶段验证：录像与侧库兼容 → 身份安全的持久队列和触发 → Web 序列及授权和 Flutter 游标 → 两端测试和构建。保持本地候选，不推送、不部署生产。
