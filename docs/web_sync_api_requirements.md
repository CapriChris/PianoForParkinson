# Web 增量同步约定和待办

本次在 Web 候选源码实现了 SQLite 版本的变更索引。安装顺序为录像修订 `l8a0b2c4d6e8` 后应用 `m9b1c3d5e7f9`。不改变任何现有业务表；不适用 MySQL 的版本会明确返回 501。生产地址当前仍是旧协议，不能据本次测试宣布生产已支持。

- 写入、更新、删除由事务内 SQLite trigger 写入增量索引。每个患者/类型/ID 保留最新事件位置；支持同一时间戳的不同记录，传输为至少一次，客户端按实体 ID 幂等应用。
- 所有页都重新授权；撤销绑定或患者权限返回 403，客户端清掉该范围缓存和游标；游标绑定操作者、绑定 ID、患者及索引代。401 需重新登录，409 需清掉旧游标后重新建立缓存，旧服务器 404/501。
- App 本地原始训练记录上传是不可变插入，来源 ID 冲突返回 409，保留本地内容，不采用最后写入覆盖。Web 患者/工作人员目录由 bootstrap 分页读取；独立目录增量、MySQL 支持、两个端同时编辑同一临床计划仍需另外实现和审批。
- SQLite 索引为删除实体保留 tombstone，不能在未实现游标水位和重建机制时随意清空。生产需评估规模、备份、触发器写入开销及恢复后的游标清理策略。
- 验收样例：三个写入用 limit=2 分成两页；删除第一条后只返回 tombstone；撤销绑定后旧游标返回 403；伪造游标返回 409。已在本地真实 FastAPI 与 SQLite 上运行。
