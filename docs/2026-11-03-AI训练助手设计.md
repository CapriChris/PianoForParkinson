# 琴伴 AI 训练助手设计

2026-11-03 · v0.1 · 设计稿

## 1. 产品范围

AI 训练助手支持自由提问、单次练习点评和近期训练复盘。普通问题按问题本身作答。用户授权后，涉及个人表现的问题可以引用琴伴的练习记录，解释观察到的变化，并给出可执行的下一步建议。

首版保留「首页、练习、计划、记录」四项底栏，新增独立聊天页。建议可以由用户自行采纳，助手只读训练数据。琴伴的练习、记录和随包舞蹈视频继续支持离线使用。CausalNet 微表情和摄像头接入留待单独设计与验证。

## 2. 入口和页面

| 入口 | 初始状态 | 用户可做什么 |
| --- | --- | --- |
| 首页 | 主要练习入口下方放「AI 训练助手」卡片。进入后无选中记录 | 自由提问，或点「回顾近期训练」「我该怎么开始练习？」 |
| 钢琴曲目、钢琴练习、舞蹈的完成页 | 结果卡片下方放「请 AI 点评」。进入后在输入框上方显示「本次练习 · 项目名」 | 提问或点「点评这次练习」。只有成功保存且可读取的记录才可预选 |
| 历史记录详情 | 复用完成页入口，关联标签用「练习日期 · 项目名」 | 回看指定记录，并与条件相近的历史练习比较 |

三个入口打开同一个聊天页。顶部只有居中的「AI 训练助手」和返回键。预选记录标签放在输入框上方，可点开查看或移除。移除后仍可按新问题授权查询近期数据。

答案下方单独显示**本条回答实际引用的记录**。例如「参考了 3 次《欢乐颂》练习 · 50 BPM」，点开查看日期和详情。普通问答没有引用时直接展示正文。即使输入框上有记录标签，问「在哪里设置提醒？」也走普通问答。页面沿用琴伴现有主题、字号、高对比度和中英文布局。

## 3. 问题如何确定记录范围

1. **普通问题**。如「怎么设置重复提醒？」不读取本地训练记录。琴伴操作类问题优先参考随应用版本维护的简明帮助。用户问应用之外的话题也可以按普通问答处理。
2. **指定练习**。用户在问题里明确指定项目、日期或记录时，以该范围为准。「这次」优先指当前选中记录，也可以指同一会话刚讨论过的明确记录。从首页进入且没有明确指向时，助手可以请用户确认，或让用户选「最近一次」。
3. **近期表现**。从首页问「我最近练得怎么样？」可以在获授权后按钢琴练习、曲目、舞蹈分别汇总。问「最近弹《欢乐颂》有进步吗？」则缩小到这首曲目。完成页问「比之前有进步吗？」以预选记录为基准寻找同条件样本。
4. **资料不足**。没有记录、记录无法读取、有效样本太少或条件差异较大时，说明已有证据和可比较的范围。比如只有一次练习时可以点评这一次，暂不判断趋势。用户明确问另一项目时，该问题优先于预选记录。

开发默认建议为最近 14 个本地日。宽泛复盘按项目提供次数与完成概况，具体趋势最多附 5 条同条件样本。用户明确指定日期时，以指定日期为准，并在结果中说明实际覆盖范围和样本数。上述数值是可调整的产品参数。

App 根据快捷入口、选中记录和问题表达自动判断是否需要查记录。聊天页没有范围选择和训练记录开关。普通问题直接作答，相关问题在本机查询记录。训练摘要获得授权后才加入在线请求。

## 4. 训练摘要

App 通过现有本地记录与趋势查询读取当前使用者的数据，先验证记录，再按字段白名单生成摘要。完整记录继续保存在 SQLite。建议复用 `PracticeRepository` 的详情与趋势校验路径，同时确保所有 AI 读取入口都限制为当前本地档案。

| 数据 | 首版可提供 | 比较规则 |
| --- | --- | --- |
| 钢琴曲目 | 曲目、日期、速度、匹配与总音符数、错键次数 | 优先同曲目版本和速度。速度变化时列出不同条件，分别描述 |
| 钢琴练习 | 项目、模式、难度、有效样本数和该项目已有指标 | 优先沿用现有可比条件与指标版本。不同项目分别报告 |
| 舞蹈跟练 | 课程、日期、分段、播放时长、到达结尾的分段数 | 只反馈播放和跟练安排。播放指标无法证明用户完成了动作 |
| 训练计划 | 与问题相关的计划目标次数、实际次数和达成状态 | 采用 App 已计算的进度，说明统计日期 |

训练次数、匹配率、变化量、样本数由 App 计算。模型收到的是摘要、必要的单位和比较条件，负责解释结果。每条证据附请求内临时编号，App 保留编号和本地记录的映射。模型引用训练数字时返回对应指标键，后端检查编号和指标键是否匹配，App 从本地渲染证据卡和具体数字。校验未通过时可以重试一次，仍失败就显示本地摘要和「暂未生成 AI 解读」。

例如两次《欢乐颂》都在 50 BPM，匹配数从 42/61 变成 51/61，助手可以建议「下次先保持 50 BPM，看看能否稳定达到这次的表现」，并注明只有两次同条件记录。

## 5. 授权和数据边界

- 「结合训练记录」首用默认关闭。用户从完成页进入也可以先看到本地预选标签。首次发送需要个人训练数据的问题时，说明会发送的问题、摘要类型、用途及处理方，提供「结合记录发送」与「仅发送问题」。预选记录本身不会触发上传。
- 用户可从设置撤回在线授权。本机查询独立运行。撤回后，后续请求停止发送训练摘要和包含该摘要的旧对话轮次。已提交给服务端的请求按告知的留存和删除规则处理。
- 不传本地档案 ID、完整数据库、原始按键轨迹、人脸图像或视频。训练数据与普通聊天均按服务实际处理情况告知用户。服务端默认不记录问题、摘要和回复正文，运行日志仅保留请求编号、状态、延迟和用量。
- AI 可以解释练习表现。对病情、诊断、用药调整或明显不适的问题，引导用户联系相应的专业人员。后续若处理涉及敏感个人信息的训练或微表情数据，先评估处理必要性、适用规则和单独同意方式。[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 6. 技术方案与失败处理

**Flutter App → 琴伴 HTTPS 后端 → 大模型 API**。用户发送问题时才调用。后端保管 API 密钥，统一处理模型配置、提示词、超时、输入长度、调用额度和返回校验。后端只接收本轮必要摘要，无权查询 App 数据库。第一版保持免登录体验，采用可撤销的安装级凭证、限流和全局预算控制接口滥用。

| 接口环节 | 设计约定 |
| --- | --- |
| 请求 | 问题、语言、请求编号、必要的会话上下文，以及经授权的可选训练摘要 |
| 响应 | 回答正文、可选的下一步建议、引用编号和样本限制。服务端校验字段类型与引用范围 |
| 多轮对话 | 只续接与本轮有关的上下文。切换范围时重新选取证据。撤回授权后，从发送上下文中移除已引用训练摘要的轮次 |
| 网络中断、超时或额度用尽 | 保留用户输入并给出具体提示。手动重试前重新核对授权和引用范围。其他页面可以继续使用 |
| 引用失效或数据不足 | 告知记录无法读取或样本不足，允许重新选择。禁止以模型生成的数字补齐 |

聊天输入框和圆形向上箭头共用一个圆角容器。新版客户端通过 `Accept: text/event-stream` 请求流式回答。网关逐段转发模型生成的正文，校验通过后再发送完整答案、下一步建议与引用。流式请求中断时移除未完成的正文，并允许重试。旧网关的普通 JSON 回复仍可显示。[DeepSeek 流式接口](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/) · [阿里云 Web 函数 SSE](https://help.aliyun.com/zh/functioncompute/does-function-compute-support-sse-streaming-response)

## 7. 实施与验收

1. **页面原型**。用本地模拟结果验证三个入口、记录标签、普通问答、授权、答复引用和历史回跳。
2. **真实数据**。接入现有练习摘要，验证数据隔离、旧记录、无样本、不同速度和损坏记录。钢琴和舞蹈分别核对指标口径。
3. **后端内测**。配置服务商、凭证、超时和预算，使用脱敏样例验证普通问答、个性化问答、错误引用、超时、拒绝授权和撤回授权。
4. **发布验收**。首页能复盘近期训练，完成页和历史页能引用正确记录，普通问答不带训练摘要。检查 360 dp、大字号、中英文、断网和权限撤回。用预设问题核对引用记录、可比条件、数字与建议，并确认安装包中没有模型密钥。

首版待定事项包括模型供应商、后端部署位置、预算与额度、聊天是否需要在本机长期保存。开发默认只保留当前会话，便于先验证问答与数据授权流程。

## 8. 运行与接入

当前工作区已有 Flutter 页面、授权、记录摘要、引用回跳和 Python 网关实现。默认构建使用本机摘要与常用帮助，可直接验证首页、完成页和历史入口。在线问答需要把网关部署到可由 Android 访问的 HTTPS 地址，并连接支持 JSON 输出的 Chat Completions 服务。

### 网关

在服务主机设置以下环境变量，再运行 `python tools/assistant_server.py`。网关只监听本机 `127.0.0.1:8080`，用 HTTPS 反向代理对外转发 `/v1/install` 和 `/v1/chat`。

| 环境变量 | 用途 |
| --- | --- |
| `QIN_AI_MODEL_URL` | 完整的模型 Chat Completions HTTPS 地址 |
| `QIN_AI_MODEL_KEY` | 模型密钥，由服务主机的密钥配置提供 |
| `QIN_AI_MODEL` | 模型服务商分配的模型 ID |
| `QIN_AI_SIGNING_SECRET` | 随机签名密钥，至少 32 字节。保持重启前后一致 |
| `QIN_AI_DAILY_CALLS`、`QIN_AI_INSTALL_DAILY_CALLS` | 全局和每安装凭证的每日模型调用上限，默认 100 和 15，以 UTC 日计。模型回复格式异常后的重试也计入额度 |
| `QIN_AI_QUOTA_DB` | 配额数据库路径，部署时放在持久可写的服务目录 |
| `QIN_AI_PORT` | 本地监听端口，默认 8080 |
| `QIN_AI_TRUST_LOCAL_PROXY` | 仅在可信本机反代会覆盖 `X-Real-IP` 时设为 `1`，让 IP 限流按用户出口生效 |
| `QIN_AI_DISABLE_THINKING` | 对支持 `thinking` 参数的服务可设为 `1`，用于关闭推理模式 |

应用首次在线提问时获取匿名安装凭证，凭证到期后会重新获取。网关不会保存聊天正文或训练摘要。配额数据库保存短期计数及签名后的 IP 分组标记。反向代理也应关闭正文日志，并限制请求大小与连接频率。

### App

在 `app` 目录使用自己的网关地址和服务商名称运行。以下为命令示例。

```powershell
flutter run --dart-define=QIN_AI_GATEWAY=https://ai.example.com/ --dart-define=QIN_AI_PROVIDER_NAME=DeepSeek --dart-define=QIN_AI_PRIVACY_VERSION=1
```

构建 APK 时将相同的 `--dart-define` 参数传给 `flutter build apk --release`。APK 只使用公开网关地址和用于告知用户的服务商名称。端点或数据处理规则变化时更新授权版本号，让已安装用户重新授权。模型密钥和签名密钥只在服务端配置。

上线前使用国内手机网络验证真实模型调用、超时、额度、撤回授权和证据回跳。模型供应商的地域与留存条款以实际账号配置和正式协议为准。

### USB 真机联调

保持电脑上的网关进程运行，用 USB 连接手机并允许 USB 调试。使用 `adb devices -l` 确认真机序列号，再在 `app` 目录执行以下命令，把 `DEVICE_ID` 换成该序列号。

```powershell
adb -s DEVICE_ID reverse tcp:8080 tcp:8080
flutter build apk --debug --dart-define=QIN_AI_GATEWAY=http://127.0.0.1:8080/ --dart-define=QIN_AI_PROVIDER_NAME=DeepSeek
adb -s DEVICE_ID install -r build\app\outputs\flutter-apk\app-debug.apk
```

签名相同且版本号符合 Android 升级要求时，`install -r` 覆盖安装并保留训练记录。遇到签名冲突时先保留已装应用。调试版允许使用 `127.0.0.1` 的 HTTP 网关，正式版要求 HTTPS。拔插 USB 或转发失效后重新运行 `adb reverse`。修改网关地址后重新构建，热重载不会应用新的构建参数。
