# 训练视频采集实施与 Web 交接

日期：2026-11-04。工作区开发版，尚未发布 GitHub Release，尚未部署到线上 Web。

## 已实现

- 钢琴七项练习、钢琴曲目和舞蹈准备页增加默认关闭的面部采集入口，明确同意后使用前置摄像头，无音轨。系统权限和本次上传授权分开处理。
- 正式训练联动开始、暂停、继续、结束。后台和退出释放摄像头；舞蹈拖动、分段、倍速及横竖屏切换记录时间关系。录制失败不修改练习计分。
- 完成后先保存原训练记录，录像独立封装，关联本次真实记录 ID。用户放弃的练习不提交录像。既有退出时保留已完成部分的规则保持原样。
- 本机录像封装后，使用 Android Keystore 的 AES-GCM 分为加密块保存。上传时只解密一块，单块 4 MiB，不将完整录像放入 Dart 内存。录制期间编码器仍使用私有缓存临时文件，异常遗留文件按时清理。
- 应用级内存登录会话供训练页面复用。退出账号和身份变化中止提交，不把工作人员密码或 token 写入 SQLite。
- 默认等待 Wi-Fi；前台可恢复上传，移动网络需明确确认；前台恢复时可继续待处理任务。服务端分块去重、块及整文件摘要核对，重复完成不会重复分析。
- 完成页和历史详情显示面部分析状态；设置页「面部采集与上传」集中查看待提交视频、连接档案及删除。视频不会自动发往 DeepSeek 问答网关。
- Web 增加训练录像父任务、断点接口和 Alembic 迁移。分段候选在 Web「随访与报告 → 软件端记录 → 详情 → 训练面部录像」复核，确认后才进入现有真实 CausalNet 推理队列。
- 分析结果保留模型版本、类别分数、质量和源片段位置。不平均成整场情绪或康复分数。分析失败可在原素材仍有效时重试，无需重新上传。
- 云端取消/删除与晚返回结果相互校验，删除录像不删除原始练习成绩。未完成上传 24 小时到期；待复核最长 7 天；终态录像 24 小时后清理归属原片副本，结构化结果按记录保留。

## 当前限制

1. **线上 Web 尚未修改。** 旧服务不会报告 `face_recordings_ready=true`，App 将说明服务暂不可用，不会把长录像错误发往旧的 50 MiB 短片接口。
2. **仍需人工复核候选。** 当前 CausalNet 流程没有经过验证的全自动选帧确认，上传成功不等于分析已经完成。
3. 本版是前台可恢复上传。系统强制停止 App 后不会承诺继续传输；重新打开并登录、绑定原档案后继续。未增加后台摄像头或持久工作人员登录凭证。
4. 录制初始上限为 30 分钟、约 400 MiB，存储接近上限会停止采集并保留训练。帧率、编码能力和舞蹈播放并发仍需真机验证。
5. 已完成相机平台模拟、真实媒体编码/分段和接口测试，**没有完成真机摄像头 → 已部署 Web → 实际权重输出的端到端验收**。技术测试不代表模型准确性验证。
6. 一期依赖工作人员帮助绑定档案，未新增患者自助账号体系。Web 服务保持单实例 dispatcher 的部署边界，未实现多实例队列。

## Web 维护者接入步骤

这是部署交接步骤，本轮未远程执行。先确认目标服务和数据库备份，再按团队现有发布流程操作。

1. 在 Web 仓库检查补丁。目标版本与基线不一致时先处理冲突，不能覆盖队友的新改动。

   ```bash
   git apply --check /path/to/web-training-face-video.patch
   git apply /path/to/web-training-face-video.patch
   ```

2. 确认服务用户可执行 `ffmpeg`、`ffprobe`，并支持 H.264 编码。建议使用服务器发行版包管理器安装 FFmpeg。既有 CausalNet 源码、权重及独立推理环境保持原配置。

3. 在服务端环境中启用：

   ```dotenv
   TRAINING_VIDEO_ENABLED=true
   MICRO_EXPRESSION_ENTRY=causalnet
   ```

   只有启用配置、选择 CausalNet 且 FFmpeg 工具可用时，完整训练录像能力才开放；模型是否就绪另由原能力检查返回。

4. 使用原后端 Python 环境迁移。**不要用本机测试虚拟环境替换线上环境。** 新迁移只增加 `face_recordings`，不变更原训练指标与患者记录。

   ```bash
   cd backend
   python -m alembic upgrade head
   ```

   预期迁移版本：`l8a0b2c4d6e8`。既有数据库启动逻辑不会自动升级已有业务表，必须执行迁移。

5. 执行后端与前端检查，构建前端，再按原部署流程发布两端并重启单实例服务。反向代理应保留 HTTPS、Authorization 及现有 `/pd-rehab/api/` 路径转发；分块请求为 4 MiB，仍需允许该请求体及足够上传超时。

   ```bash
   python -m pytest tests/test_training_face_recordings.py tests/test_cross_client_integration.py tests/test_integration_hardening.py
   cd ../frontend
   npm ci
   npm run test
   npm run build
   ```

6. 登录后调用 `GET /api/integration/v1/capabilities`，确认 `face_recordings_ready` 和 `face_model_ready` 都为 `true`，协议修订为 `1.2`。

7. 用测试档案做手机联调：准备页开启 → 允许相机 → 完成短训练 → 成绩保存 → 上传完成 → Web 预览并确认候选 → 等待结果 → App 刷新 → 历史回读 → 删除录像并核对成绩仍保留。
