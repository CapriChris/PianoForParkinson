## 队友真机操作

1. 安装预发布地址对应 QA 包，首次启动仅看到登录/注册；返回键不能进训练。
2. 注册 A，主动勾选同步授权，保存恢复码并确认；看到本人患者编号。拒绝同名工作人员注册与非法密码长度。
3. 完成引导，创建目标 2 次计划，第一次训练后 Web 显示 1/2，第二次为 2/2；反复同步和重开 App 不增加版本、不回退进度。
4. 断网训练，退出页面/重启 App，已验证且未过期账号可恢复本地记录；联网后上传一次。首次登录或已失效身份不能离线假成功。
5. 退出 A，登录 B，历史、计划、AI 会话和录像不得看到 A；重新登录 A 后原历史仍在。旧访客目录保持原样，不自动上传。
6. 后台联网与系统调度测试：先正常退出到桌面，观察任务执行；在省电/强制停止状态明确记录系统限制。前台正在训练时，不让后台读取未完成会话或抢写工作区。
7. 杀进程、设备重启后检查 Keystore 恢复；过期/改密后回到登录；服务端撤销后的旧媒体链接拒绝访问。
8. 独立同意录像后验证原有相机、加密保存、人工上传和 Web 播放下载/复核/结果回读。账号注册不等于同意录像，结构化后台任务不自动录制或上传视频。

## 回滚

优先停止分发新 App、切回旧 UI 或禁用新注册，并保留新表和合法用户数据。旧 Web代码不理解 PATIENT，回滚前需停用新 PATIENT、撤销相关会话或验证旧版鉴权不会放行；不能只切代码便默认安全。

`n0→m9` 已在临时库测试：保留旧患者/训练，停用 PATIENT，移除移动账号/会话表。生产一旦已有新注册或业务写入，不能自动破坏性 downgrade，也不能用旧库覆盖新库；应制定保留新数据的迁移方案后审批。

App 可回到旧安装包，但新账号目录及密文不删除。旧访客数据库继续保留。密钥失效时只处理对应凭证/账号恢复，不清空全局训练数据。除明确批准的目标服务外，不改 Nginx、端口、其他项目或共享账号。
