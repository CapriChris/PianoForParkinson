# 0.1.4 G2／G3 验证

日期：2026-10-14；Android 内部演示。Medium Phone / emulator-5554 / API 37。自动化测试使用随机命名独立数据库，用户连接的物理手机未安装或清除数据。

## 规则与记录

- G2 每组 12 项、9 GO／3 NO_GO、GO 三键各三次、最多两次连续 NO_GO；LCG＋Fisher–Yates，32 次重试和固定后备类型序列。100 个种子验证平衡、连续限制与复现。
- G3 六个 r≠s 有序组合各两次；A／B 目标映射、等级 1～5 的 run_length、首项 null／其后切换标志及 SQLite 规则列核对。正式前四次互动例子没有写入记录。
- GO 错后补对仍 WRONG_KEY，对后再按为 EXTRA_RESPONSE；等待任一键／空白／禁用操作为 COMMISSION。首末窗口边界、持续按住、间隔操作、规则标题及释放等待、普通暂停／辅助重试、手动降级均覆盖。
- G2 单列 GO／NO_GO 分母，G3 单列规则及切换分组；反应时间仅 HIT，切换差需两类各至少 5 个无帮助样本。错误或未完成尝试没有伪造反应时间。
- 首次动作和 tick 捕获统一操作时间，逐读递增时钟测试验证 end−1 μs 不被内部多次读取误判为窗口外。窗口 end 时刻输入不归前一 trial。
- 组及会话封存使用现有事务、自适应和比较键；重启保留完整组，排除未完成窗口，并生成部分会话摘要。旧 G1／S1 分数不重新计算；schema 仍为 v1。

## 验证结果

130 个独立单元／内容／布局用例通过：原 75 + G2／G3 领域 35 + 页面布局 20。页面用例覆盖两任务 640×360／800×360、中／英文、字号 1.0／2.0 的信号／暂停／结果；另有四个 360×640 试玩布局用例。固定琴键图形和当前规则实际可见，未增加独立暂停滚动面板或继续练习按钮。

真实 MonotonicClock＋SoundPool 流程验证 G2／G3 完整窗口、普通暂停保留 attempt 和刺激、首个有效结果落库及左上角返回；已有 G1／S1 真实声音流程也通过，包含注入写失败退出及首页重试、状态栏隐藏与恢复。

最终串行完整流程复测通过。覆盖 G2／G3 各两组、四个试玩不落库、暂停、成绩、趋势、G3 规则列、两种任务的进程恢复，以及既有 G1／S1 各两组流程。本轮共执行并通过 6 个独立 Android 集成用例：新增完整流程 1、进程恢复 2、真实时钟／声音流程 1，以及已有 G1／S1 完整流程 1、真实声音／失败保存退出流程 1。

曾出现一次测试调度失误：两轮模拟器测试重叠安装 APK，中断了旧流程；该次不计为通过，最终改为串行重跑。旧菜单脚本还曾在滚动后立即点击落在底部导航附近的歌曲按钮，已改为对准可见区域、等待布局完成并检查实际可点击；该次也不计为通过。统计不把重复运行算作新用例。

本轮没有再次执行原生契约、保存压力及历史分页集成套件，保留前版报告。虚拟时钟的完整 UI 流程验证逻辑和真实 SQLite，不代表物理练习剂量或声音延迟。最低 API 24、蓝牙／有线、TalkBack、患者操作矩阵仍未在本轮验证。
