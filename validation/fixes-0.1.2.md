# 0.1.2 首次弹奏保存与暂停交互验证

日期：2026-10-14。Android 内部演示，实际使用 Medium Phone / API 37 模拟器。没有在用户连接的物理手机上安装或清除数据。

## 修复原因

旧版在 cuePresented 和结果封存时分别多次读取 MonotonicClock。同一逻辑锚点／结束边界产生数微秒差值，严格时长校验失败。推进时钟回归测试在修复前分别复现 G1、S1 相差 1 微秒；修复后锚点和结束时间各捕获一次，仍保持严格校验。

布局快照还可能在页面转场结束前捕获。现在等待转场及横屏／全屏请求就绪后再开始，避免首个输入使旧转场坐标重新测量。

## 用户要求与验证

| 要求 | 验证 |
| --- | --- |
| 左上角返回可以退出，无新返回首页按钮 | G1 保存后退出到首页；S1 注入写失败仍从左上角退出，首页提示未保存并可重试 |
| 暂停菜单与琴键同屏 | 640×360／800×360，中／英文，文字比例 1.0／2.0 共 8 用例；普通字号整组菜单在琴键上方且所有操作可点击，大字号在既有上方内容区滚动可达 |
| 删除底部需要帮助和独立继续按钮 | 控件查找确认训练页不存在这些按钮 |
| 顶部状态栏隐藏，退出恢复 | 原生实际 WindowInsets 状态与 training_fullscreen 标志在进入后和退出后分别断言；退出检查等待系统栏恢复动画，最多 1 秒 |
| 右上角暂停／继续，不重播 | 实际触摸右上角按钮，G1 弹第一个键后暂停、S1 首个键前暂停；继续时同 attempt、同 response 阶段，DEMO 请求数不增加，最终有效结果落库 |
| 暂停冻结时间与策略 | 7 个领域用例覆盖窗口、首次响应、S1 自动高亮、示范中途继续、显式帮助、退出和已弹错误保留 |
| 首次有效弹奏不导致保存失败 | 开启原生声音＋真实 MonotonicClock，G1／S1 首个有效试次保存成功，未误入暂停；另有 2 个逐次推进时钟回归 |

静态分析无问题。56 项单元／内容／布局用例、6 项 Android 集成用例均通过（全套中系统栏异步恢复检查曾失败，加入有界等待后仅复测该新增流程并通过；其余 5 项在全套运行通过）。

保存压力场景仍覆盖 200 对 DOWN／UP、100 次技术中断、5,000 MOVE；新版继续不自动重播示范，事件总数变为 6,630，全部落库且外键无异常。本轮场景总耗时 17,152 ms，不是单次延迟或物理输入测量。

schema 表结构保持 v1；新增结果字段 paused_duration_us／user_pause_count 及 block 的 pause_policy。恢复中的 OPEN attempt 仍中断处理，不继续旧进程时钟。专业评审、物理设备音频延迟与完整 D1／D2 验收不在本轮结论内。

release 构建、最终 APK 哈希、安装／冷启动和权限元数据以 ../build-report.json 为准。
