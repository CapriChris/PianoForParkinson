# 0.1.1 数据与稳定性验证

日期：2026-10-14。内部演示，参数未评审。

用户反馈已完成真机验证；没有提供型号、系统版本、验证项目或延迟报告。本轮自动化使用 Android 17 / API 37 模拟器，独立随机 no-backup 测试目录。没有在已连接手机上安装、清除数据或执行测试。

## 自动化范围

- 39 个单元／内容／布局用例：新增 12 项记录与统计回归；8 个布局用例增加展开详情的中英双语、手机／平板和系统文字比例 1.0／2.0 校验。最终审查另验证 LCG 合法的零中间状态；初始种子仍须非零。
- 原生契约：真实 SoundPool 和 SQLite、generation、唯一有效尝试、外键、删除级联、重启恢复。
- UI 流程：经页面完成 G1／S1 两组、保存结果、返回首页。
- 三个稳定性用例：通过 SQLite trigger 注入首批事件失败、组摘要失败；检查整个事务回滚，重试仍使用同一 commit_id，无重复升级或摘要；终态重试不改时间、结果和档案。
- 已写事件内容被改动时 E_EVENT_CONFLICT；封存结果被改动时 E_RECORD_CONFLICT。失败后库中旧记录不变。
- 200 次按下／松开、100 次中断重试、5,000 MOVE，累计 7,430 个事件；分批刷新后事件数一致、外键无异常、重新打开库保留 EXITED 和唯一有效结果。
- 非终态重启恢复为 RECOVERED_INTERRUPTED，恢复摘要不计未完成尝试；旧引擎不能继续覆盖。schema 校验和不匹配时拒绝打开并保留原库。

上述压力操作由引擎虚拟时钟生成并写入 Android SQLite。早期一次压力场景总执行时间 20,172 ms；后续全套运行中为 18,644 ms，最后稳定性复测为 18,740 ms。这是整个模拟场景时间，包括多批事务及校验，不是单次声音、触摸或数据库提交延迟指标。

新包构建和最终测试状态以 ../build-report.json 为准。schema 仍为 v1，本轮没有数据库结构升级；后续 v2 的有序迁移、私有临时备份和只读错误页仍需实现。全配置／环境解码、NFC、无限长会话内存、系统备份／设备转移测试不在本轮通过结论内。
