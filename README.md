# 琴伴 · Android 内部演示

当前开发版本 **0.1.53+54**。内部演示包：[琴伴 0.1.53](../releases/琴伴-0.1.53-internal.apk)。

## 从仓库构建

仓库根目录对应原项目的 `app` 目录。安装 Flutter、Android SDK 和 JDK 后，在仓库根目录执行：

```powershell
flutter pub get
flutter analyze
flutter test
flutter run -d <Android设备ID>
```

当前开发环境使用 Flutter 3.47.7、Dart 3.13.5 和 JDK 21。历史记录中指向 `../环境配置`、`../设计修订` 和 `../releases` 的链接属于原工作目录，不包含在此仓库中；本地构建和验证产物也未上传。

## 0.1.27 横屏滚动长条曲谱

## 0.1.4 G2／G3

- **弹奏与等待（G2）**：每次 2 组，每组 9 GO＋3 NO_GO；GO 的三个目标键各出现 3 次，最多连续两个 NO_GO。按完整响应窗口判定命中／漏按／错键／额外响应／正确等待／等待误按。显示 GO 命中与 NO_GO 误按各自的分母，正确等待不会抬高 GO 正确率。
- **位置与图形（G3）**：K0 三角、K1 圆、K2 方形。规则 A 按位置，规则 B 按图形；六个不同位置／图形组合各两次。每组从 A 开始，按等级连续 6／4／3／2／1 项后切换；窗口只由模式决定。第一项 switch_flag=null，SQLite 规则列与目标快照一致。
- G3 开始前提供 A、B 各两个不计分、不落库的互动例子，可重复或跳过。正式规则标题至少 1,500 ms；信号提示区不作为答案输入区。固定图形在大字号下仍保留。
- 两项任务都等待完整窗口结束，间隔 700 ms，下一提示再等全部触点松开 300 ms；记录实际间隔，间隔触摸不分配给下一试次。普通暂停保留同一目标／attempt，冻结窗口，不重播；技术中断、帮助和降低难度仍走明确的辅助／替换流程。
- 结果与趋势支持 G2／G3。HIT 才产生反应时间；G3 分别显示规则 A／B、切换／重复规则表现，只有切换与非切换各至少 5 个无帮助 HIT 样本才显示中位数差。
- 输入与 tick 每次捕获一个单调时钟操作时间，避免连续读取跨越微秒窗口边界。已通过 end−1 μs 仍在窗口内、end 时刻在窗口外的回归。自动调整按各任务规则执行，决定中的参数快照使用实际调整后窗口／run_length。

schema 和原参数配置仍为 v1，不修改上游数值，不需要数据库迁移。130 项单元／内容／布局用例通过；完整 Android 流程的最终串行验证与 release 信息见 [0.1.4 验证](validation/cognitive-0.1.4.md)。

## 文件结构

- `lib/domain`：单调时钟、LCG、任务、判定与自适应；不依赖 Flutter UI 或数据库。
- `lib/app`：启动、主题、语言、会话与平台／记录协调。
- `lib/features`：琴键和训练页；页面集合当前在 `lib/app/piano_app.dart`，后续按功能拆分。
- `lib/data`：内容哈希、SQLite、事务、记录及中断恢复。
- `lib/platform`：版本化 MethodChannel／EventChannel 桥。
- `android`：SoundPool、本地 TTS、音频焦点、私有路径、备份规则。
- `assets/config`：参数和 SQL；音量与配置版本按 0.1.5 设计修订更新。
- `assets/content`、`assets/audio`：实际内容包、音源清单及原创 WAV。
- `tools/build_sampled_piano.py`：固定上游 revision 的采样重建、原始文件 SHA-256、变调／裁剪与内容清单；`tools/generate_audio.py` 仅保留早期合成音的历史构建器。

所有音源与曲目标记为 `DEVELOPMENT_ONLY`，训练参数仍为 `UNREVIEWED / INTERNAL_DEMO`。参数中的 `audio.assets_ready=false` 保留上游模板值；实际启动能力由真实文件 SHA-256 校验和 SoundPool 加载结果计算，不用修改该布尔字段伪装素材就绪。
